--------------------------------------------------------------------------------
FILE 1: app.py
--------------------------------------------------------------------------------
Path: app.py

WHAT WAS THERE PREVIOUSLY:
- Flask was initialized with default settings: `app = Flask(__name__)`.
- The server ran on default port 5000: `app.run(debug=True)`.

WHAT WAS CHANGED:
1. `app = Flask(__name__, template_folder="Templates")`
   - Why: Your folder is named "Templates" with a capital 'T'. On some operating
     systems (like Linux), folder names are strictly case-sensitive. Explicitly
     setting `template_folder="Templates"` guarantees that Flask finds the HTML
     files on any computer or server.

2. `port = int(os.environ.get("PORT", 5000))`
   `app.run(debug=True, port=port)`
   - Why: On macOS, port 5000 is often taken by AirPlay Receiver. Allowing a PORT
     environment variable (e.g. `PORT=5050 python app.py`) gives you the flexibility
     to run on any port without code edits.

FILE 2: routes/student_routes.py
--------------------------------------------------------------------------------
Path: routes/student_routes.py

WHAT WAS THERE PREVIOUSLY:
- Only one route existed: `@student_bp.route("/")`
- It ran `SELECT * FROM students` and rendered `index.html`.
- No form submission handling, no add route, no edit route, no delete route.

WHAT WAS ADDED & HOW IT WORKS:

1. Input Validation Helper Function (`validate_student_data`):
   - Validates that Name is not empty and is under 100 characters.
   - Validates that Email is not empty, is under 150 characters, and matches standard
     email regex pattern (`user@domain.com`).
   - Cleans the phone number (removes spaces, hyphens, parentheses) and checks that
     it contains between 10 and 15 digits.
   - Returns a clean result or an informative error message.

2. Updated Home Route (`GET /`):
   - Queries students in ascending order:
     `SELECT id, name, email, phone, created_at FROM students ORDER BY id ASC`
   - Calculates dynamic counts:
     * `total_students`: total count of students.
     * `active_records`: active student records.
     * `email_records`: count of students with an email address.
   - Passes all counts into `index.html`.

3. New Add Student Route (`POST /add`):
   - Receives form data (`name`, `email`, `phone`).
   - Validates the inputs using `validate_student_data()`.
   - Checks MySQL if the email already exists (`SELECT id FROM students WHERE email = %s`).
     If it does, it displays a friendly error instead of crashing with a database error.
   - Inserts the new record:
     `INSERT INTO students (name, email, phone) VALUES (%s, %s, %s)`
   - Commits changes to MySQL (`mysql.connection.commit()`).
   - Shows flash message: "Student added successfully!".
   - Redirects back to home page (`/`) to display the new student immediately.

4. New Edit Student Route (`POST /edit/<int:id>` and `POST /edit`):
   - Receives student ID and updated fields.
   - Validates inputs.
   - Checks that the student exists in MySQL.
   - Checks if the new email is already taken by a DIFFERENT student:
     `SELECT id FROM students WHERE email = %s AND id != %s`
   - Updates the database row:
     `UPDATE students SET name = %s, email = %s, phone = %s WHERE id = %s`
   - Commits changes to MySQL.
   - Shows flash message: "Student details updated successfully!".
   - Redirects to home page (`/`) with updated values immediately visible.

5. New Delete Student Route (`POST /delete/<int:id>` and `POST /delete`):
   - Receives the student ID to delete.
   - Verifies the student exists in the database.
   - Executes:
     `DELETE FROM students WHERE id = %s`
   - Commits changes to MySQL.
   - Shows flash message: "Student deleted successfully!".
   - Redirects back to home page (`/`).

6. Exception Safety & Rollback:
   - Every database route uses `try ... except ... finally`.
   - If an error happens at any point, `mysql.connection.rollback()` is executed,
     protecting the database from corrupted state, and the cursor is safely closed.

3. STEP-BY-STEP EXPLANATION OF HOW CRUD WORKS NOW
================================================================================

1. CREATE (Add a Student):
   Step 1: User clicks "+ Add Student" button on the dashboard.
   Step 2: Bootstrap modal (#addStudentModal) opens smoothly.
   Step 3: User fills in Name, Email, and Phone number.
   Step 4: Browser validates formats (required, email structure, 10-15 digits).
   Step 5: Form posts to `/add`.
   Step 6: Flask checks for duplicate emails and validates inputs.
   Step 7: Record is inserted into MySQL `students` table.
   Step 8: Flask flashes "Student added successfully!" and redirects to `/`.
   Step 9: Page reloads with the new student in the table and updated statistics.

2. READ (Viewing Directory & Stats):
   Step 1: Whenever `/` is requested, Flask queries MySQL for all students.
   Step 2: Flask counts total students, active students, and email counts.
   Step 3: Jinja2 renders each student in a clean table row with their ID, Name,
           Email, Phone, and Action buttons.
   Step 4: Statistics cards at the top show the exact counts.

3. UPDATE (Edit a Student):
   Step 1: User clicks the blue outlined "Edit" button on any student row.
   Step 2: JavaScript reads `data-id`, `data-name`, `data-email`, and `data-phone`
           from that specific button.
   Step 3: The Edit modal (#editStudentModal) opens with fields pre-filled with
           that student's current information.
   Step 4: User updates any field and clicks "Save Changes".
   Step 5: Form posts to `/edit/<id>`.
   Step 6: Flask ensures email is not taken by another student and updates MySQL.
   Step 7: Flask flashes "Student details updated successfully!" and redirects to `/`.
   Step 8: Page shows the updated information in the table immediately.

4. DELETE (Remove a Student):
   Step 1: User clicks the red outlined "Delete" button on a student row.
   Step 2: A confirmation modal (#deleteStudentModal) pops up with:
           "Are you sure you want to delete this student? Student: [Student Name]"
   Step 3: If user clicks "Cancel", the modal closes; nothing is deleted.
   Step 4: If user clicks "Yes, Delete", the form posts to `/delete/<id>`.
   Step 5: Flask deletes that record from MySQL using its primary key `id`.
   Step 6: Flask flashes "Student deleted successfully!" and redirects to `/`.
   Step 7: The student is removed from the table and the count decreases by 1.

4. SEARCH, FILTER & SORT FUNCTIONALITY
================================================================================

1. Search (Name, Email, Phone):
   - Users can type any search term into the search bar.
   - SQL query performs:
     WHERE (name LIKE %s OR email LIKE %s OR phone LIKE %s)
   - Works across first names, last names, email addresses, and phone numbers.

2. Filters (Department, Course, Admission Year):
   - Department Filter: Filter by Computer Science, Information Technology,
     Data Science, Artificial Intelligence, etc.
   - Course Filter: Filter by B.Tech, M.Tech, BCA, MCA, etc.
   - Admission Year Filter: Filter by 2022, 2023, 2024, 2025, 2026, etc.
   - SQL dynamically applies WHERE conditions:
     AND department = %s
     AND course = %s
     AND admission_year = %s
   - Dropdowns auto-submit upon selection for instantaneous filtering, or can be
     submitted via the Search button.
   - Displays active filter badges with a one-click "Clear Filters" button.

3. Sorting (Name & Student ID):
   - Sort by Student ID (Ascending): 1, 2, 3...
   - Sort by Student ID (Descending): Newest records first.
   - Sort by Name (A to Z): Alphabetical order.
   - Sort by Name (Z to A): Reverse alphabetical order.
   - SQL query applies:
     ORDER BY {id|name} {ASC|DESC}

4. Updated Database Schema:
   - Added `department` (VARCHAR(100), default 'Computer Science').
   - Added `course` (VARCHAR(100), default 'B.Tech').
   - Added `admission_year` (INT, default 2024).
   - Add and Edit modals updated with suggestions (<datalist>) and input fields.
   - Table columns updated with stylish, modern badges for Department, Course, and Year.

5. DATABASE QUERIES SUMMARY
================================================================================

- Read, Search, Filter & Sort:
  SELECT id, name, email, phone, department, course, admission_year, created_at 
  FROM students 
  WHERE 1=1 
    AND (name LIKE %s OR email LIKE %s OR phone LIKE %s)
    AND department = %s
    AND course = %s
    AND admission_year = %s
  ORDER BY {sort_column} {order};

- Check Duplicate Email on Add:
  SELECT id FROM students WHERE email = %s;

- Insert New Student:
  INSERT INTO students (name, email, phone, department, course, admission_year) 
  VALUES (%s, %s, %s, %s, %s, %s);

- Check Duplicate Email on Edit:
  SELECT id FROM students WHERE email = %s AND id != %s;

- Update Existing Student:
  UPDATE students 
  SET name = %s, email = %s, phone = %s, department = %s, course = %s, admission_year = %s 
  WHERE id = %s;

- Delete Student:
  DELETE FROM students WHERE id = %s;

6. HOW TO RUN THE APPLICATION
================================================================================

To start your Flask application, open your terminal in the project directory
and run:

    ./venv/bin/python app.py

If port 5000 is occupied on your Mac (by AirPlay/ControlCenter), run:

    PORT=5050 ./venv/bin/python app.py

Then open your browser and navigate to:
    http://127.0.0.1:5050
